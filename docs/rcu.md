## 页面和接收边界

新增顶层“增程器”页签，展示运行状态、发动机/FISG 转速、输出电压/电流/功率、冷却液和电机温度，
以及机油、尿素、累计发电量、功率限制、软件版本、指示灯和故障信息，共 45 个非预留状态/参数字段。
电流及功率保留协议符号：负值为发电、正值为耗电。

只解析已经收到的 RCU 扩展数据帧，不发送查询、控制、唤醒或启动请求。
CAN Monitor 手动发送、NORMAL 模式及其正常链路 ACK 保留；电池页、记录、曲线和邮件行为保留。
不会自动更改用户信号定义，RCU 数值解码不依赖曲线配置。

## 淡红色 ID 标记

严格按矩阵 **AG 列 RCU=s** 判定发送方，并精确匹配下列九个扩展 ID。
CAN Monitor 主表背景为淡红 `#ffe1e1`，原 BMS 天蓝色不变。

| 消息 | 扩展 CAN ID | 周期 | 矩阵行 | 主要内容 |
|---|---|---|---|---|
| RCU4 | `0x1404949C` | 1000 ms | 63–70 | 发动机转速、冷却液、尿素温度/液位/浓度、机油压力 |
| RCU5 | `0x1405949C` | 1000 ms | 71–81 | 发动机指示灯 |
| RCU6 | `0x1891949C` | 20 ms | 82–91 | RCU 状态/处置等级、高压急停、FISG 转速/扭矩/温度 |
| RCU7 | `0x1892949C` | 20 ms | 92–100 | 电流、功率、允许发电功率、故障等级、主动放电状态、暖机请求 |
| RCU8 | `0x1893949C` | 1000 ms | 101–104 | 累计发电量、输出电压、允许耗电功率 |
| RCU9 | `0x1894949C` | 5000 ms | 105–111 | 软件版本、产品代号、日期字段 |
| RCU10 | `0x1896949C` | 1000 ms | 112–116 | 三类平均发电功率、需求功率 |
| RCUDTC1 | `0x18019894` | 1000 ms，IfActive 信号 | 117–255 | 故障分组号与故障位图 |
| RCUDTC2 | `0x1895949C` | 1000 ms | 256–257 | RCU 原始故障代码 |

`RCUDTC1` 的 ID 地址字节与其他 RCU 报文不同，但矩阵明确标记 RCU 发送，按原值实现。
不采用“末字节是 9C 就着色”的推测，不将 HCU 下发命令或其他地址同 PGN 标为 RCU。
标准帧、未知 ID 和其他源地址不参与此精确标记。

## 解码约定

信号均按矩阵 J 列 **Intel**、L 列全局起始位、O 列长度解码：
`物理值 = 无符号原始值 × Q列Resolution + R列Offset`。
包括非字节对齐的 10/12/30 位字段，不能先拼成有符号 32 位再统一位移。

| 代表字段 | 起始位 / 位长 | 换算 | 协议物理范围 |
|---|---|---|---|
| 发动机转速 | RCU4 0 / 16 | raw × 0.125 rpm | 0–8032 |
| 冷却液温度 | RCU4 16 / 8 | raw − 40 °C | −40–210 |
| FISG 转速 | RCU6 8 / 16 | raw rpm | 0–8032 |
| FISG 扭矩 | RCU6 24 / 16 | raw − 5000 N·m | −5000–5000 |
| 输出电流 | RCU7 0 / 16 | raw − 5000 A | −5000–1000 |
| 输出功率 | RCU7 16 / 16 | raw − 2000 kW | −2000–2000 |
| 累计发电量 | RCU8 0 / 24 | raw kWh | 0–16777215 |
| 输出电压 | RCU8 24 / 16 | raw V | 0–1000 |
| 三类平均/需求功率 | RCU10 0/12/24/36，各 12 位 | raw − 2000 kW | −2000–2095 |

完整 45 个字段定义在 `main/web_rcu.h` 的 `RCU_FIELDS`，每项带原矩阵行号。
协议未填写的 Invalid/Error 列不补造 `FF` 哨兵值；超出矩阵物理范围时才显示无效读数。
因此累计电量 `0xFFFFFF`、12 位功率 `0xFFF`、版本字段最大值及故障代码 255 都按原表保留。

运行状态 `stREX`：0 初始化、1 未就绪、2 就绪、3 启动、4 停机、5 怠速、6 怠速充电、
7 正常充电、8 靠边停车/跛行、9 高压电池耗电。未定义枚举显示原始十六进制值。
控制处置等级为正常/降功率/强制怠速/停机，4 为预留；系统故障等级另按 0–3 显示。
指示灯严格使用矩阵枚举，不把未定义值一律当“灯灭”。
年份字段未给纪元，页面显示原始年份字段，不自行增加 2000。
RCU6 计数器与校验和四位字段仅展示原始值，工作簿未提供校验算法，未假设 XOR 或 CRC 规则。

## 分组故障

RCUDTC1 Byte0 为分组号，按具体信号中的 `m1`–`m5` 分别提取故障。
矩阵分组描述仅提到 1–4，但第 254–255 行明确定义 `m5`，因此按详细位表支持第五组。
137 个故障位分布不连续；例如第二组故障 46 为 bit8、故障 78 为 bit45，第五组故障 137 为 bit9。
不通过“故障编号递增即位号递增”生成映射，也不把未定义位当作已定义故障。

各组独立缓存并独立判断新鲜度，新零位图只清除本组旧故障。
协议只提供“RCU故障1”等编号，未提供部件含义；页面保留编号，不编造中文部件解释。
RCUDTC2 同样保留原始代码，不将其编号未经依据地对应到位图故障。
IfActive 报文未收到不表示没有故障，超时也不代表故障解除。

## 缓存、API 与超时

接收任务在原有 RX 数据帧路径更新 RCU 缓存，RTR 和标准帧不更新。
8 个非复用 ID 各一槽、RCUDTC1 五组各一槽、未知分组一诊断槽，最多 14 帧，
不依赖主表十条历史、128 ID 槽，也不依赖曲线/录制。清空主表或 ID 淘汰不会清除此缓存。

`GET /api/messages` 增加顶层 `rcu` 数组，沿用 `{seq,t,id,dlc,ext,data}` 原始帧格式。
`rcu[].seq` 与电池缓存一样填 0，不用于历史序号；相同 DTC ID 可出现多个分组帧。
未收到时为 `[]`；旧字段和 `battery` 数组不变。网页沿用原有轮询，不增加 CAN 请求。

年龄使用帧 `t`、`clk.boot` 和浏览器经过时间计算，重复读取缓存不会令旧帧变新。
应用层默认 10 秒超时，5 秒周期的 RCU9 使用 15 秒；这是页面规则，不是协议另行给定的 Timeout。
缺失、断线、短 DLC、异常字节、越界、未知枚举和超时分别显示，不能补成零。
设备 `boot` 变化清掉浏览器旧缓存，32 位开机毫秒回绕得到正确年龄。
