# 完整记录与 CSV 导出

点击自定义曲线页的 Record 后，设备按本次启用信号的 CAN ID 保存原始帧；网页按记录编号和连续帧序号读取，每批最多 128 帧。网页对每帧解码一次，解码结果同时用于曲线窗口和完整记录。曲线窗口滚动不会删除 CSV 数据。

停止时设备固定最终帧数，网页自动补取未读取的帧，并确认已连续处理全部帧。状态显示“同步完整”后可下载或邮件发送 CSV。补齐/确认失败会保留源记录和本地数据，自动重试，也可点击“重试同步”。请等待同步完成，再关闭页面或开始新记录。

CSV 每个原始帧一行，包含 `no,time_rel_ms,信号(单位)@ID,...`；`no` 从 0 开始，与记录帧序号对应，同时间戳的不同帧分别保留。其他 ID 的信号、长度不足或无效解码结果留空，不补零，不使用曲线上的 `k` 等数值缩写。下载和邮件使用同一生成过程。数值使用 JavaScript Number；原始整数提取支持 64 位，但超过 53 位的整数转为物理值时可能舍入，当前预置的四个 16 位信号不受影响。

本次信号配置在开始时固定，编辑、删除、导入及保存新配置用于下次录制，不改变本次记录的解码规则和 CSV 列。配置保存状态明确区分待保存、成功和失败；设备已保存的空配置不会被旧浏览器缓存恢复。

## 容量与恢复

- 记录缓冲最多 6MiB，每帧 18 字节，最多 349,525 帧。当前两路报文合计 120 帧/秒时约 48.5 分钟；实际容量以页面为准。内存不足时降级分配，并为系统保留至少 512KiB PSRAM 余量。
- 录满自动停止，最后一帧保留，旧数据不覆盖。容量满表示达到录制上限，不代表原计划时长已完成。
- 断网或页面刷新后，可在设备仍保存同一记录时重新读取、解码并补齐；同步完成后的本地记录可以离线下载。
- PSRAM 是易失存储。设备断电或重启会丢失设备内记录；已下载的 CSV 不受影响。发现源记录消失或改变时，页面保留已有本地数据并提示，不会把未同步的数据标成完整。
- 浏览器完整缓存使用分块类型化数组，安全上限 256MiB；CSV 下载上限 128MiB，邮件附件上限 20MiB（邮箱账户可能更低）。达到限制或分配失败会报告错误并保留源数据，不截断后冒充完整导出。
- 多个页面同步同一记录时，设备最多保留 8 个同步保护槽，每次读取续期 15 秒。另一页面仍在补齐时不能替换记录；关闭页面后保护自动过期。同步确认响应丢失可重试，设备保留最近 8 份确认回执。

“同步完整”表示设备保存的帧已全部处理。TWAI 接收队列丢失、溢出及无法确认的状态单独显示，不能据同步完成推断总线上绝对零丢帧。该计数覆盖总线接收，不能定位丢失帧是否属于本次目标 ID。

## API

`POST /api/rec/start` 的 body 为 `{ "signals": [...] }`，返回 `{ok,rec,signals}`。`rec.session` 为 16 位十六进制记录编号；`cnt` 是帧数，帧序号从 0 开始。`POST /api/rec/stop` 使用 `{session}`，停止后帧数固定。

`GET /api/rec/status` 返回当前状态和固定信号配置。`GET /api/rec/data?session=...&client=...&from=...` 返回 `{ok,rec,from,next,frames}`；`client` 为每个页面独立的 16 位十六进制标识，`frames` 最多 128 帧，各帧带 `{seq,t,id,dlc,ext,data}`。

客户端仅在全部帧处理成功且记录已停止后发送 `POST /api/rec/ack`，body 为 `{session,client,count}`，成功回执为 `{ok:true,session,count}`。新记录前显式发送 `POST /api/rec/release` 的 `{session,client}`；其他页面仍在同步或设备备用导出时返回 409。`/api/rec/clear` 也不能绕过保护。

停止后访问 `/api/export` 异步下载备用原始帧 CSV，列为 `no,time,id,dlc,ext,data`，响应头 `X-Record-Session` 标识来源。本次信号配置仍可从 `/api/rec/status` 获取；自定义解码宽表使用网页导出。

兼容旧版无 body 的 `POST /api/rec/start`：只记录 `0x18FF0182`、`0x18FF0282`，无固定自定义信号配置，此模式 `/api/export` 保留旧版物理值列。已有受保护记录不能被旧版接口覆盖。
